# Fix headroom first, then teach Cadence to listen

Cadence's sound engine is already better than most of what it competes with, but three things hold it back. It is missing the library plumbing every rival ships. Its output stage clips hot masters. And its old AI design sent the whole library to an LLM on every request. **The most audible problem in Cadence today is not bit depth or shared mode: it is a hard `clamp(-1, 1)` in the cpal callback, applied with no headroom stage, sitting in front of the Windows audio limiter.** When a 0 dBFS master is resampled, the true-peak overs that result are hard-clipped, and that distortion lands in the 5–22 kHz region. This, together with level mismatch, is the most likely reason a 24/48 FLAC sounds worse in Cadence than in Apple Music. On features, the gap to Strawberry, MusicBee, Harmonoid and Plexamp is mostly Windows media integration (SMTC), ReplayGain, tag editing, playlists and smart playlists, scrobbling, synced lyrics, folder watching and a real database. Mature, permissively licensed Rust crates cover nearly all of it: `wasapi`, `ebur128`, `lofty`, `rusqlite`, `notify`, `windows`, `realfft`, `bs2b`, plus official Tauri v2 plugins. For AI, the commercial winners (Plexamp's sonic analysis and Guest DJ, Spotify's Prompted Playlist and Taste Profile, Apple's Playlist Playground) and the open-source reference AudioMuse-AI all follow the same rule: **local retrieval picks the candidates, and the LLM only parses, curates, names and explains.** That cuts per-request cost from about 80k tokens to about 4k, removes hallucinated tracks, and keeps listening history on the machine. The recommended path has seven phases. Phase 0 is a one-week sound-quality fix. Then come a SQLite foundation, library power features, pro audio (exclusive mode and parametric/AutoEq EQ), local sonic analysis with CLAP via ONNX, and finally a grounded, provider-agnostic LLM layer.

## Cadence trails rivals on library plumbing, not on audio

Cadence already does what many players still get wrong. It has gapless playback with sample-aligned resampler swaps, a high-quality FFT resampler, an f64 biquad EQ, and an honest signal-path display. What users say "premium" means comes down to one idea: **automatic, context-aware behavior that never misfires**. Plexamp is praised for Sweet Fades, pre-caching and Guest DJ. Its best-known complaint is that fades "ruin favourite albums", and Plex answered that complaint by turning fades off automatically when the user plays an album ([Plex forum](https://forums.plex.tv/t/sweet-fades-sometimes-not-so-sweet/647568)). Apple Music on Windows shows the opposite failure. It fails silently on files it cannot play, and its library breaks when files move, because it stores aliases ([Apple Support](https://support.apple.com/guide/music-windows/mus3081/windows), [Apple Community](https://discussions.apple.com/thread/255948349)). That gives Cadence an open lane: foobar2000-class library power behind a Plexamp-class interface, with explicit errors and a library that survives moved and renamed files.

Two engineering lessons should shape scheduling. First, exclusive mode is hard to get right. foobar2000 rewrote its WASAPI exclusive output and kept fixing end-of-track glitches for several releases ([Neowin](https://www.neowin.net/amp/foobar2000-21/)). WaveFlow, a Tauri + cpal player that added a Rust exclusive backend, hit the same traps Cadence will: the shared stream must be released before the endpoint is reopened, device loss must route through the rebuild path, a "settle window" is needed for the echo `DeviceNotAvailable` from the old stream, and recovery must reopen the user's pinned device ([WaveFlow PR #429](https://github.com/InstaZDLL/WaveFlow/pull/429)). Second, the current JSON library file rewrites the whole library on every scan. Play counts, scrobble queues, lyrics caches, ReplayGain values and embeddings all need SQLite, so the database migration blocks most of the roadmap.

## Clipping and level, not bit depth, are what Cadence's listeners hear

The current chain is: symphonia decode to f32, then `map_channels`, the 10-band RBJ EQ in f64 at the source rate, rubato `Fft` resampling to the device mix rate, a 0.5 s ring buffer, and finally the cpal callback, which does `(v * volume).clamp(-1.0, 1.0)` and outputs in WASAPI shared mode at `default_output_config()` (`mod.rs`, lines 748 and 802–807). There is no gain stage anywhere before the clamp.

That matters because **inter-sample overs are normal in commercial masters**. They reach up to +3.01 dBFS in theory and +0.5 to +1.5 dBFS on real CDs; Steely Dan's "Gaslighting Abbie" has 1,129 overs. Resamplers and oversampling DACs that lack headroom clip these overs into bursts of non-harmonic distortion, "most of [it] between 5 kHz and 22 kHz" ([Benchmark Media](https://benchmarkmedia.com/blogs/application_notes/intersample-overs-in-cd-recordings)). Cadence resamples a 24/48 file to the 96 kHz shared mix rate, which turns those inter-sample peaks into real sample values above 1.0. The user measured +0.6 dBTP. The clamp then hard-clips them. Whatever survives lands in the Windows engine, whose CAudioLimiter APO "steps in and pulls the signal closer to the center" once samples approach about 0.985 of full scale ([van Eerde, Microsoft](https://matthewvaneerde.wordpress.com/2011/05/11/linearity-of-windows-volume-apis-iaudiometerinformation-and-full-scale-signals/)). Later analysis traced the poor measurements of the Windows 10 resampler mainly to this full-scale limiting, not to the resampler, and a few dB of headroom made it go away ([The Well-Tempered Computer](https://thewelltemperedcomputer.com/SW/Windows/SRC.htm)). Apple Music almost certainly plays such a track lower, through Sound Check or a different master, so it avoids both stages. It also wins any unmatched A/B test for another reason. The comparison is confounded by level, and level differences of about 1 dB are enough to bias preference, a well-known result for which no specific study was retrieved. **The fix is headroom and loudness matching, not a better resampler.**

### Concrete fixes to the current Cadence code

Several of these fixes are a few lines each, and together they form Phase 0 of the roadmap.

**1. Add a gain stage in `Worker::step()`, after `map_channels` and before the EQ and resampler.** Apply the gain there and not in the callback. The ring holds 0.5 s of the previous song, so a gain applied in the callback would switch half a second early or late. Use ReplayGain 2.0: gain_dB = (−18 − integrated LUFS) + preamp, capped at gain ≤ −20·log10(peak) − 1 dB, where peak is the true peak. For untagged files, apply a fixed −3 dB "safety headroom" until a scan completes. Album gain is the default for album playback and track gain for shuffle. Scan in the background with `ebur128` (modes I and sample peak, with true peak optional because it is costly) on the existing rayon pool. Read existing `REPLAYGAIN_*` Vorbis, `TXXX` and iTunes tags through lofty, and watch for the known unit bug: some FLAC tools write the reference loudness as negative LUFS where others expect dB SPL ([GStreamer #2821](https://gitlab.freedesktop.org/gstreamer/gstreamer/-/issues/2821), [opus-tools](https://gitlab.xiph.org/markh/opus-tools/-/blob/ef87ba9330fd59b1ef56b5811be63c49b3536450/src/flac.c)). On a modern pop master this yields roughly −8 to −10 dB. That one change cures the clamp clipping, the Windows limiter and the level mismatch with Apple Music at once.

**2. Compute an automatic EQ preamp from the combined biquad magnitude response.** Evaluate the cascade over 20 Hz–20 kHz and take its maximum. Do not simply use the largest band gain: overlapping Q 1.41 bands add up, so presets such as "Acoustic" (−4 dB preamp with adjacent +4 dB peaks) still exceed 0 dB.

**3. Clamp only for integer device formats.** For f32 shared output, pass samples through unchanged, and drive a peak meter and a UI "clipping" indicator above 0.985. With fixes 1 and 2 in place, nothing should reach that threshold. An optional look-ahead true-peak limiter can stay off by default, because headroom is the cure and a limiter on every track is a coloration.

**4. Replace the multichannel-to-stereo fold, which drops the center and LFE channels.** `map_channels` keeps only `f[0]` and `f[1]` for any input with more than two channels (lines 730–734). A 5.1 FLAC therefore loses its center channel, and with it the vocals. That is the one clearly audible bug in the chain unrelated to level. Implement an ITU-style downmix: L' = L + 0.707·C + 0.707·Ls, R' = R + 0.707·C + 0.707·Rs, with LFE optional, followed by normalization or headroom.

**5. Make `bit_perfect` honest.** The flag at lines 686–689 ignores both shared mode and the clamp. In shared mode, APOs and the limiter (and vendor "enhancements") still touch every sample. Rename the shared-mode state to "unaltered by Cadence", and reserve "bit-perfect" for exclusive mode with gain, EQ and resampling all bypassed. Then adopt Roon's tiers: lossless, enhanced (DSP or leveling applied), and altered (OS mixer) ([Roon KB](https://kb.roonlabs.com/Signal_Path)).

**6. Add a WASAPI exclusive backend.** Add an `OutputBackend::{Cpal, WasapiExclusive}` enum behind the existing `Output`. The exclusive thread pops the same `HeapCons<f32>` and updates the same `Shared` atomics, so the gapless `Boundary` logic stays untouched. Run it event-driven on an MMCSS "Pro Audio" thread. Probe formats in this order: source rate at 24-in-32, then 32-bit integer, then 24-bit packed, then 16-bit with TPDF dither. Reopen the device when the sample rate changes between tracks, which makes the only gap a rate change; same-rate tracks stay gapless. In exclusive mode, apply volume digitally in Cadence, because session volume does not reach exclusive streams. Microsoft's own guidance shapes the UX: exclusive mode "seize[s] the audio endpoint", silencing all other sounds, so apps should "always provide a user-visible option to fall back to shared mode" ([Microsoft Learn](https://learn.microsoft.com/en-us/windows/win32/coreaudio/exclusive-mode-streams)). Over the user's S/PDIF link, exclusive mode at 48 kHz removes Cadence's resampler entirely and lets the DAC oversample. That is the most correct path, but once headroom is in place it should be audibly indistinguishable from a clean 96 kHz SRC.

**7. Smaller fixes.** Add a 10–30 ms fade on seek, skip and pause; today `flush_output` cuts hard and can click. Use a dB-tapered volume slider (a UX fix, not a fidelity one). Verify that `Source::open` enables symphonia's gapless handling for MP3 and AAC encoder delay. Optionally use `Fft::new_custom` with a high-attenuation window and check aliasing with a −1 dBFS sweep. The 0.5 s ring latency on EQ changes is cosmetic.

### Separating the audible from the placebo

| Classification | Items |
|---|---|
| **Clearly audible** | Clipping and limiting of hot masters; level mismatch; frequency-response correction (headphone/speaker EQ); multichannel downmix loss; crossfeed (a preference change); room correction below about 300 Hz |
| **Measurable, rarely or never audible** | rubato vs soxr vs r8brain; f32 vs f64 processing; float vs integer output at 24 bits or more; dither at 24 bits; shared vs exclusive *when rates match, nothing else is mixing and headroom is kept* |
| **Marginal under ideal conditions** | Hi-res vs 16/44.1: a Reiss meta-analysis of 18 experiments and more than 12,500 trials found a "small but statistically significant" discrimination effect, about 60% for trained listeners ([QMRO](https://qmro.qmul.ac.uk/xmlui/handle/123456789/13493?show=full)) |
| **Placebo or marketing** | Upsampling 44.1/48 to 192 kHz for its own sake; "bit-perfect" as an audible property in itself; MQA; DSD conversion of PCM sources; noise-shaped dither at 24 bits |

Rubato's `Fft` mode is documented as its highest-quality fixed-ratio resampler, with "no quality settings; it always delivers the best quality" ([docs.rs rubato](https://docs.rs/rubato/latest/rubato/)). No published stopband figures exist for it, so a quick local measurement is worthwhile, but swapping in libsoxr would be a measurable-only gain. Deliberate upsampling adds no information. Its only real benefit is moving the anti-imaging filter away from a DAC with a poor or non-oversampling filter, and its real cost is turning more inter-sample overs into true sample overs.

### Measured EQ is the largest real upgrade a player can offer

Frequency-response errors of several dB dwarf every bit-level concern. AutoEq generates corrections for thousands of headphones from oratory1990, crinacle and Rtings measurements toward targets such as Harman over-ear 2018. Its `ParametricEQ.txt` output uses low shelves, peaking filters and high shelves, each with its own Q, plus a precomputed preamp (−6.1 dB for the HD 650) ([AutoEq](https://github.com/jaakkopasanen/AutoEq), [HD 650 file](https://raw.githubusercontent.com/jaakkopasanen/AutoEq/master/results/oratory1990/over-ear/Sennheiser%20HD%20650/Sennheiser%20HD%20650%20ParametricEQ.txt)). Cadence's fixed-Q, peaking-only graphic EQ cannot reproduce this. The upgrade path is short. Generalize `eq.rs` to a list of `{type: PK|LSC|HSC|LP|HP, fc, gain, q}` filters, since the RBJ cookbook already provides the shelf formulas and the f64 direct-form-I code is unchanged. Then add an Equalizer APO importer and keep the 10-band UI as one preset type. Treat "Rock" and "Pop" presets as taste, not fidelity. Crossfeed through the `bs2b` crate is a real but preference-level change: the default is 700 Hz / 4.5 dB, Chu Moy is 700 Hz / 6 dB, and Jan Meier is 650 Hz / 9.5 dB ([bs2b](https://bs2b.sourceforge.net/)). Ship it off by default. FIR convolution for REW room correction and ISO 226-style loudness compensation at low volume come later, because the user's endpoint (headphones or speakers behind the S/PDIF DAC) is still unknown.

## Retrieval first, LLM second: rebuilding Cadence's AI

The old C#/WinUI Cadence treated the LLM as the entire recommender. `MixesAsync` and `AskAsync` serialized the whole library as numbered `id|title|artist|genre|year|plays` lines, sent it to Z.ai GLM with temperature 0.8 and no JSON schema, and recovered results by taking the substring between the first `{` and the last `}` and repairing duplicated keys (`AiService.cs`). The taste model was sound in spirit: plays weighted by exp(−days/30), skips at −0.5, a "skipped artist" rule, hour-of-day genres, and favorites at +1.5. But it was flattened into a text summary (`TasteService.cs`). Five failures follow from this design. Token cost grows with the library: about 60–100k tokens for 5k tracks, an estimate. The LLM cannot know what an obscure or local track sounds like. Positional ids broke between calls. There was no schema enforcement. And the full library plus a behavioral log went to a cloud provider on every request.

### What the commercial products actually teach

Spotify's DJ is "recommender picks, LLM narrates, TTS speaks". OpenAI writes the commentary from editor-supplied facts; the lineup comes from Spotify's personalization system ([Spotify Newsroom](https://newsroom.spotify.com/2023-02-22/spotify-debuts-a-new-ai-dj-right-in-your-pocket/)). Spotify's 2026 direction is about control. Prompted Playlist auto-refreshes daily or weekly and lets users edit the prompt ([The Letter Two](https://thelettertwo.com/2026/01/22/spotify-prompted-playlist-ai-music-discovery/)). Taste Profile lets users exclude playlists and tracks from learning ([MBW](https://www.musicbusinessworldwide.com/spotify-to-let-users-edit-the-algorithm-behind-their-personalized-recommendations-with-taste-profile)). Daylist's time-of-day titles drive a reported 70% weekly return ([Digital Music News](https://www.digitalmusicnews.com/2023/09/12/spotify-daylist-launch/)), but critics say the titles often don't match the contents ([Varsity](https://www.varsity.co.uk/music/27712)). Apple's Playlist Playground (iOS 26.4, March 2026) set the now-standard pattern: a prompt produces a 25-song playlist with a generated title, description and cover, plus suggestion chips and conversational refinement ([9to5Mac](https://9to5mac.com/2026/02/16/ios-26-4-beta-adds-new-playlist-playground-ai-feature-in-music/)).

The model that matters most for Cadence is Plexamp, because it works on a library the user owns. A neural network on the user's server maps every track into a vector space, and "sonically similar" means nearby points ([TechCrunch](https://techcrunch.com/2021/08/12/plexs-new-feature-matches-your-sonically-similar-music-to-make-playlists/)). Track and album radio, Mixes for You, Sonic Adventure (a path from track A to track B) and the Guest DJ modes are all nearest-neighbor queries or simple queue transforms on top of it ([PR Newswire](https://www.prnewswire.com/news-releases/plexamp-adds-sonic-sage-chatgpt-based-feature-for-creating-incredible-playlists-301814850.html)). In Freeze, a few similar tracks follow the current one; in Gemini, one similar track follows each queued track. Users love these because each mode is small, named and predictable ([Plex forum](https://forums.plex.tv/t/guest-dj/816330)). The top complaint is that modes silently do nothing while analysis is incomplete ([Plex forum](https://forums.plex.tv/t/plexamp-dj-freeze-does-not-work/926088)). Roon supplies the cautionary counterexample. Its Valence radio leans on crowd and streaming signals, and local-only users report it does little for them ([Roon Community](https://community.roonlabs.com/t/does-valence-support-non-streaming-users/84742)). Cadence's discovery must therefore come from its own audio embeddings and local history. For a library with no catalog, "discovery" largely means **rediscovery** of forgotten favorites.

AudioMuse-AI is the open-source proof that the whole Plexamp stack runs locally. It computes MusiCNN (200-d) and CLAP (512-d) embeddings via ONNX and searches them with an int8 IVF index. Song Path interpolates between endpoints with artist caps. CLAP text search handles "rainy late-night piano" with no LLM. Its "Instant Playlist" sends a single tool-calling LLM request whose tools run real library queries, so results cannot be hallucinated. Its taste vector is a 30-day-half-life weighted average of play-history embeddings ([ALGORITHM.md](https://github.com/NeptuneHub/AudioMuse-AI/blob/main/docs/ALGORITHM.md)).

### Local audio embeddings: two tiers, and the licensing trap

| Option | What it gives | License | Fit for Cadence |
|---|---|---|---|
| bliss-audio (Rust) | DSP features (tempo, timbre, chroma); Euclidean similarity; about 0.35 s/track parallel aggregate with pure-Rust symphonia ([bliss-rs](https://github.com/Polochon-street/bliss-rs)) | **GPL-3.0** | Only if Cadence is GPL; otherwise reimplement a small BPM/key/loudness/centroid set |
| LAION-CLAP (music checkpoints) via `ort` | Similarity + zero-shot mood/genre + offline text-to-music search; 48 kHz input; about 790 MB fp32 for both towers ([LAION-CLAP](https://github.com/LAION-AI/CLAP), [ONNX export](https://pypi.org/project/muzaiten-features-clap/)) | CC0 repo | **Best default for "Smart analysis"**; optional download |
| Essentia Discogs-EffNet / MAEST | Better-calibrated mood, danceability and genre heads; ONNX available; 16 kHz ([Essentia](https://essentia.upf.edu/models.html)) | CC BY-NC-SA 4.0 | Non-commercial builds only |
| MERT, MuQ-MuLan | Strongest music representations ([MERT](https://huggingface.co/m-a-p/MERT-v1-95M), [MuQ](https://huggingface.co/OpenMuQ/MuQ-MuLan-large)) | CC-BY-NC 4.0 | Avoid |

`ort` 2.0.0-rc.15 wraps ONNX Runtime 1.31 ([docs.rs ort](https://docs.rs/crate/ort/latest)). Cadence already decodes with symphonia and resamples with rubato, so feeding CLAP two or three 10 s windows from mid-track at 48 kHz mono reuses existing code. No controlled CPU benchmark was found for CLAP or EffNet, so Cadence must benchmark on its own hardware before promising analysis times. Vector search needs no special infrastructure at this scale. 100k tracks × 512-d f32 is 205 MB, and a brute-force SIMD cosine pass takes tens of milliseconds; 5k tracks take under a millisecond. HNSW only pays off at a million or more items. Store embeddings as BLOBs in SQLite, keyed by blake3 content hash so that re-tagging never forces re-analysis. `sqlite-vec` exists but is pre-v1 ([sqlite-vec](https://github.com/asg017/sqlite-vec)).

### LLM options, costs and privacy

Once the library stops going to the model, cost becomes negligible. A grounded "Ask the DJ" request (a 150-track shortlist, about 4k tokens in and 800 out, an estimate) costs about **$0.0008 on Claude Haiku 5.5 ($0.10/$0.50 per million tokens) or gpt-6-luna ($0.10/$0.50)**, about $0.001 on GLM-5.3-Flash ($0.15/$0.50), and nothing on Z.ai's free GLM-4.7-Flash ([Claude pricing](https://platform.claude.com/docs/en/about-claude/pricing), [OpenAI pricing](https://developers.openai.com/api/docs/pricing), [Z.ai pricing](https://docs.z.ai/guides/overview/pricing)). The old full-library call cost about $0.012 and ran into context limits. Note that GLM-5.3-Flash, the model the old app used, is a paid model. Gemini's free tier is cheap but **free-tier data is used to improve Google products**; paid-tier data is not ([Gemini pricing](https://ai.google.dev/gemini-api/docs/pricing)). Gemini Flash prices also double on 2027-01-01. For the fully private path, Ollama exposes an OpenAI-compatible endpoint at `localhost:11434/v1` with JSON-schema structured outputs ([Ollama](https://ollama.com/blog/structured-outputs)). Qwen3-4B is a 2.5 GB download with 256K context ([Ollama qwen3](https://ollama.com/library/qwen3)). CPU-only generation will likely take 30 s or more per mix (an unsourced estimate), which is fine for nightly mix naming and sluggish for interactive chat.

Privacy should be designed in from the start, as a three-level choice. "Off" means local similarity and shelves only. "Local AI" means Ollama or LM Studio. "Cloud AI" means the user brings a key, sees a "data sent" preview before the first call, and sends only shortlist titles, artists, genres and years plus an aggregate taste summary such as "likes city pop, 80s, mellow". Never send paths, raw timestamps, play logs or audio. Store keys in Windows Credential Manager through `keyring` 4.2 or through DPAPI, matching the old app's `ProtectedData` behavior ([docs.rs keyring](https://docs.rs/keyring/latest/keyring/)). Make every HTTP call from Rust, so the key never crosses into the webview. MusicBrainz and Last.fm lookups also leak titles and belong behind the same opt-in. Both services are free only for non-commercial use, and Last.fm adds attribution requirements and a 100 MB caching cap ([MusicBrainz](https://musicbrainz.org/doc/MusicBrainz_API), [Last.fm ToS](https://www.last.fm/api/tos)).

## A concrete architecture for Cadence

The architecture keeps the real-time path untouched by anything slow, puts all state in one SQLite database, and treats the LLM as a replaceable service at the outer edge.

```
Svelte 5 UI ──invoke/Channel──► Tauri commands (Rust)
                                   │
  ┌────────────── Playback (real-time) ───────────────┐
  │ Worker: symphonia → map_channels(ITU) → Gain(RG+headroom)
  │   → PEQ cascade(f64, auto-preamp) → [crossfeed] → rubato Fft
  │   → [crossfade mixer: 2 pipelines] → HeapRb<f32>
  │ OutputBackend: Cpal(shared, f32, no clamp) | WasapiExclusive(int, TPDF@16)
  │ Taps: peak/clip meter, visualizer ring, listened-frames counter
  └───────────────────────────────────────────────────┘
  ┌────────────── Library & services (background) ────┐
  │ SQLite (rusqlite, WAL, FTS5): tracks, albums, mbids, rg values,
  │   plays/skips/ratings, playlists+rules, lyrics cache, scrobble queue,
  │   embeddings (BLOB by blake3), ai_cache
  │ Scanner (rayon) + notify watcher → lofty tags, ebur128 loudness
  │ Net queue (reqwest, token bucket 1 req/s): MusicBrainz, CAA, LRCLIB,
  │   Last.fm, ListenBrainz (opt-in)
  │ OS: SMTC (windows crate), tray, mini-player window, single-instance
  └───────────────────────────────────────────────────┘
  ┌────────────── Intelligence ───────────────────────┐
  │ Analyzer (throttled, resumable, visible progress): DSP features
  │   + CLAP audio tower via ort (optional model download)
  │ Vector store: in-memory Vec<f32>, brute-force cosine (rayon/SIMD)
  │ Taste engine: decay-weighted taste vectors (long-term, session,
  │   hour-of-week), skip penalties, "don't learn from this" flags
  │ Recommenders: radios, Guest-DJ modes, Song Path, rediscovery,
  │   context mixes, CLAP text search — all LLM-free
  │ LLM gateway: OpenAI-compatible client (presets: Ollama, LM Studio,
  │   Z.ai, OpenAI, OpenRouter, Gemini, DeepSeek; Anthropic adapter),
  │   json_schema/tool calls, keyring-stored key, data-sent preview
  └───────────────────────────────────────────────────┘
```

The LLM request flow is the core of the AI redesign. For "Ask the DJ", the LLM first turns the user's text into a structured query of about 300 tokens, with no library data: `{mood_text, energy, tempo_range, genres[], decades[], exclude_artists[], length_min, familiarity}`. Its vocabulary deliberately mirrors the smart-playlist rule language, so one query engine serves both features. When AI is off, the CLAP text tower embeds the request directly instead. Retrieval then runs locally and scores each track as α·cos(text, track) + β·cos(taste, track), applies metadata filters, subtracts skip penalties, and keeps the top 150. Only that shortlist, encoded as stable base36 short ids derived from the blake3 hash, goes back to the LLM, which returns ordered ids, a title and a reason under a JSON schema. Local BPM, key and energy features then optionally reorder the result for flow, and every inserted track carries a visible "because you played X" explanation. Daily mixes skip per-mix prompting altogether: k-means (k = 4–6) clusters recent-taste embeddings locally, and the LLM only names each cluster from about 10 example titles plus tag summaries, roughly 1–2k tokens for all mixes. Titles therefore always match contents, which is exactly where Daylist was criticized. Results are cached per (request, library version, day), and the static system prompt is structured as a cacheable prefix. Optional DJ narration (text cards, with TTS optional) is grounded only in local tags, matching Spotify's split between picker and narrator.

## Seven phases from sound fixes to a grounded DJ

Effort figures are rough solo-developer estimates based on the scope analysis above, not measured data. The ordering puts audible correctness first, unblocks the database next, and builds AI only on top of the history and analysis that the earlier phases collect.

|---|---|---|---|
| **0. Sound-quality hotfix** | Gain stage before EQ/SRC with fixed −3 dB safety headroom; EQ auto-preamp from combined response; clamp only for integer formats plus clip meter; ITU downmix; honest signal-path tiers; seek/skip micro-fades; dB volume taper | none new | about 1 week |
| **1. Foundation** | JSON → SQLite (WAL, FTS5) with migration; play/skip/rating history logged by consumed frames; ReplayGain 2.0 scanner plus tag reading (track/album/off); SMTC and media keys; tray, close-to-tray, mini player; single-instance and file associations | `rusqlite`, `ebur128`, `lofty`, `windows`, `tauri` tray-icon, `-window-state`, `-positioner`, `-single-instance` | 3–4 weeks |

One decision must come before Phase 4: **Cadence's license.** GPL-3.0 bliss-audio, NC-licensed Essentia, MERT and MuQ models, a GPLv3 ASIO SDK, and non-commercial AcoustID, MusicBrainz and Last.fm terms each either force the project toward GPL and non-commercial use, or rule themselves out. CLAP (CC0), `ort`, `wasapi`, `ebur128`, `lofty` and `rusqlite` keep every option open. Several facts in this report remain unverified and should be checked during implementation: the exact `wasapi` 0.26 exclusive-mode API and its buffer-alignment handling; the `ebur128` multi-state album-loudness function name; whether the Windows 11 24H2/25H2 limiter still behaves as it did in 2011; CLAP's ONNX size after quantization and its per-track CPU cost; and the JSON-schema support on Z.ai's, Gemini's and DeepSeek's OpenAI-compatible endpoints.

## Conclusion

The research changes the order of priorities more than the list. The obvious move for an audiophile player is to chase exclusive mode and better resampling first. The evidence instead says Cadence's audible defects are self-inflicted gain-staging problems that a week of work removes, and that measured parametric EQ will do more for listeners than any bit-perfect badge. Exclusive mode still belongs on the roadmap, but as a correctness and honesty feature, labeled like Roon's signal path, not sold as a sound-quality upgrade.

On AI, the industry has converged on a pattern that suits a local player better than it suits a streaming service. Without a catalog, Cadence cannot do discovery the way Spotify does. It can, however, run Plexamp-grade sonic analysis on the user's own desktop, keep the entire taste profile private, and use an LLM purely as a language interface that costs fractions of a cent, or nothing locally. The old Cadence's ideas (mixes, Ask the DJ, a decay-weighted taste model) were right. They were built on the wrong substrate. Rebuilt on embeddings and SQLite history, the same features become more accurate, cheaper, and possible offline.
